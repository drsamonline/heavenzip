It never opens a compressor. It only spawns processes.

heavenzip chains prebuilt binaries — a preprocessor, then ziptastic, then a recompressor — into one .hzpkg archive. File in, one file out, and the package carries its own manifest.

Why it spawns instead of links

A boundary between licences

Some of the best compressors in the CHCE family are GPL. Linking them into an MIT binary would drag the whole thing under the GPL; spawning them keeps a process boundary between the two licences.

Nothing shared but a path

The orchestrator never sees a compressor's internals — it hands over a file path and takes back a file path. That is the entire interface.

A manifest that explains the bytes

Every package records which stage produced which part of it, so a later reader can say what happened without re-running anything.

What a run looks like

# the orchestrator spawns; it does not compress
heavenzip pack document.pdf -o document.hzpkg

# inside: preprocessor -> ziptastic -> recompressor
# and a manifest recording which stage produced which bytes

heavenzip unpack document.hzpkg -o restored.pdf   # bit-exact
